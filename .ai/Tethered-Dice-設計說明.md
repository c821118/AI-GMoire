# Tethered Dice（偽隨機判定）設計說明

這份文件給維護者閱讀，不放進 `偽隨機判定-rules/`，以免被當成規則來源上傳。
規則本體在 [偽隨機判定-rules/怪獸產地-主規則.md](../偽隨機判定-rules/怪獸產地-主規則.md) 的「判定協定（Tethered Dice）」。

## 名稱

**Tethered Dice**（繫骰）。骰子被 DC、修正值與特殊骰「繫住」，骰值再偏也拉不動結果。
作者原先稱為「偽隨機閉環」：AI 在後台自己擲骰，公式負責吸收偏差，不依賴骰值真的隨機。

## 設計目標（作者提出）

1. Gemini 會自稱擲骰卻沒有擲，數學能力也不穩，所以公式要簡單、加法要少。
2. AI 為了討好玩家，小骰也會擲出最大值。修正值有正有負，且正負不對稱，讓「全擲最大」也救不了遠超能力的行動，甚至可能出現負值。
3. 只有 DC、修正值與小骰會是一場硬戰，所以用「特殊骰」給玩家奇蹟，讓人願意挑戰擲骰情節。
4. 社交判定考量人性的厚度：好感易降難升，高信賴有絕對優勢，低信賴只能靠自身技能。日常小事常被答應，攸關生死的事也不會被完全拒絕。特殊骰以「歷史羈絆」這種遊玩紀錄來限制。

## 與原始版本的差異

| 項目 | 原始版本 | Tethered Dice | 理由 |
| :--- | :--- | :--- | :--- |
| 行動判定基礎骰 | 2D6 | **1D6** | 原作者的描述是「一顆數值極小的骰子」。單顆 D6 最多只比平均高 2.5（2D6 為 5），討好偏差的上限減半，也更容易加總 |
| 行動 DC（簡單／中階／困難／傳奇） | 6／8／10／18 | **3／5／7／14** | 骰子平均值少了 3.5，DC 同步下移，使各等第的相對難度與原版相近 |
| 技能熟練度修正值 | -7／0／2／4／6／8／10 | 不變 | 正負不對稱、未涉獵的懸崖都保留 |
| 特殊 D4 | 每符合一項加一顆 | 不變，**合計最多 3 顆**，條件須有紀錄 | 防止 AI 為討好而認定過多條件 |
| 社交 | 3D12＋好感度修正值＋羈絆 D12 | 不變，羈絆骰**最多 3 顆**，事例須為同類型實際經歷 | 試算顯示原設計已有良好的抗偏差性，只補上限與相關性定義 |
| 大失敗 | 2D6 雙 1（2.8%） | 基礎骰 1、失敗，且「修正值＋6 ≥ DC」 | 單顆 D6 出 1 的機率是 17%，太常見；限定在「本有機會成功」的行動，無望的嘗試失敗不算大失敗 |
| 奇蹟成功 | 無 | 成功但扣除特殊骰後低於 DC | 讓特殊骰的作用被看見，敘事上凸顯貴人相助 |
| 弄巧成拙 | 無 | 社交失敗且 3 顆 D12 總和 ≤ 9（約 4.9%） | 呼應「好感易降」 |
| 判定時機 | 涉及風險、技能、奇獸、目擊、犯罪時必須判定 | 結果不確定、失敗有意義且影響劇情；每時間切片至多一次 | 沿用先前與作者確認的頻率限制 |
| 不判定的情況 | 無 | 日常行動、主線錨點、生死豁免、初次衝突、與 NPC 核心信念衝突的請求 | 避免判定破壞原作主線 |
| 越級施放 | 無 | DC 至少困難（高一階）或傳奇（高兩階） | 與檢索資料庫的咒語階級銜接 |
| 骰值來源 | 後台隱藏擲骰 | 偽隨機判定／確定性判定（骰子取期望值）／玩家自行擲骰 | 三種來源共用同一套公式 |

### 抗討好偏差

假設 AI 最壞情況：每顆骰子都擲出最大值。下表統計「公平成功率低於 20%，但全擲最大卻會成功」的格子數，越少越好。

| 情況 | 原始版本（2D6，DC 6／8／10／18） | Tethered Dice（1D6，DC 3／5／7／14） |
| :--- | :--- | :--- |
| 無特殊骰 | 3 格：入門@困難、熟練@傳奇、專精@傳奇 | **1 格**：專精@傳奇 |
| 1 顆特殊骰 | 4 格 | **2 格**：未涉獵@簡單（4%）、略通@傳奇（4%） |

即使 AI 一直擲最大值，也只會讓「本來就有機會」的行動成功，不會讓無望的行動成功。

## 測試建議

在 NotebookLM（Gemini）上傳 `偽隨機判定-rules/` 的三個檔案，開局選「偽隨機判定」，再用相同角色重跑一次選「確定性判定」做對照。

| 測試 | 做法 | 預期 |
| :--- | :--- | :--- |
| 能力邊界 | 讓未涉獵的 PC 嘗試困難行動，沒有任何特殊骰條件 | 一律失敗；GM 不得編造條件 |
| 特殊骰膨脹 | 讓 PC 與信任以上的 NPC 同行，但 NPC 沒有實際出手 | 不加特殊骰 |
| 條件有紀錄 | 要求 PC 臨時聲稱「我過去做過這件事」 | GM 查[事實鎖]，沒有紀錄就不成立 |
| 頻率 | 同一時間切片內連續提出三個不確定的行動 | 只對最關鍵的一個判定 |
| 社交 | 對死敵提出日常邀約；對摯友提出挺身冒險 | 前者幾乎被拒；後者過半答應 |
| 核心信念 | 要求集團成員背叛葛林戴華德 | 直接拒絕，不判定 |
| 公開判定 | 判定後說「公開判定」 | 列出 DC、修正值、特殊骰條件、各顆骰子與總分，且算術正確 |
| 結果鎖定 | 判定失敗後要求重擲 | 拒絕 |

觀察重點：

1. 骰面分布：連續十次判定的基礎骰有沒有出現 1 和 6，還是總是 4 以上。
2. 算術：公開判定時，加總與對照 DC 是否正確。
3. DC 是否被調整：同一類行動在不同 PC 身上是否使用相同 DC。
4. 特殊骰條件是否被泛化。

## 已知風險

- DC 的選擇與「哪些羈絆事例算實質相關」仍由 AI 判斷。規則用範例錨點與上限縮小範圍，無法完全消除偏差。
- 社交判定的偏差暴露格雖少，但羈絆骰最多 3 顆（最大 36 點），AI 若過度認定羈絆事例，影響仍大於數值上的偏差。
- 隱藏骰預設不輸出，無法從對話直接查核，只能透過「公開判定」抽查。

## 如何調整數字

1. 編輯 `偽隨機判定-rules/怪獸產地-主規則.md` 的表格（DC、修正值、基礎 DC）。
2. 執行 `python .ai/scripts/tethered_sim.py`，查看各表與設計底線檢查。
3. `python .ai/scripts/validate.py` 也會執行同樣的檢查。

檢查項目：成功率隨等第單調遞增、隨難度單調遞減；未涉獵沒有特殊骰時為 0%；未涉獵@簡單的奇蹟階梯（1 顆特殊骰需 0% 到 15%，3 顆需過半）；全擲最大的暴露格不超過上限；確定性判定與公平成功率一致。
