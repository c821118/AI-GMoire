# 隨機與判定協定

## 為什麼需要這份協定
語言模型自己「想一個隨機數」並不隨機：它傾向給出符合劇情期待、或討好玩家的結果。因此本 Skill 規定，任何機率結果都必須來自可驗證的來源；取得不到來源時，就不使用機率，而不是假裝擲骰。

## 適用範圍
- 角色卡中選了「隨機」的項目，例如隨機分配的能力等第、隨機魔杖、隨機奇獸夥伴。
- 結果不確定且失敗有意義的行動判定。
- 遭遇、隨機事件與 NPC 反應。

## 一、隨機來源（依序嘗試，取第一個可用者）

**A. 程式碼執行（首選）**
- 條件：環境有可執行指令或程式碼的工具，且實際執行成功並取得輸出。
- 作法：以本 Skill 資料夾為工作目錄，執行 `python scripts/roll.py ...`（用法見下節）。無法執行該檔案但能執行 Python 時，可用單行指令，例如 `python -c "import secrets; print(secrets.randbelow(20) + 1)"`。環境內建的擲骰或隨機工具也可以。

**B. 網頁讀取**
- 條件：沒有程式碼執行，但有讀取網址的工具。
- 作法：每次需要一個新數字就讀取一次 `https://www.random.org/integers/?num=1&min=1&max=20&col=1&base=10&format=plain&rnd=new`（回傳純文字數字；`min`、`max` 可依骰型調整）。不得重複使用先前的回應。

**C. 玩家擲骰**
- 條件：以上兩者都不可用。
- 作法：GM 說明骰型與用途，請 PC 用實體骰、骰子 App 或任何線上擲骰器擲出並回報；需要多個數字時（如隨機分配）一次請 PC 提供足夠數量。PC 回報的數字即為結果。
- 公平：GM 必須先宣告難度與各結果的後果，PC 才擲骰；PC 回報後不得重擲。PC 可以隨時改選 D。

**D. 確定性判定（保底，不使用機率）**
- 條件：沒有任何可驗證的來源，PC 也不想自行擲骰。
- 作法：結果完全由規則與情境決定，不含運氣。比較 PC 的相關能力（熟練度、好感度、資源）與情境難度：明顯高於難度＝成功；相當＝勉強成功（付出代價）；明顯低於＝失敗，但失敗必須推進劇情。
- 角色卡的「隨機」項目：GM 須明說「本次無法取得隨機來源」，並由 PC 指定，或由 GM 依規則上限、職業與性格合理配置，嚴禁佯稱已隨機抽取。

## 二、確認有沒有工具
- 只有實際發出一次工具呼叫並取得輸出，才算「有工具」。嘗試失敗、被拒絕或沒有這類工具，就往下一級。不確定時視為沒有。
- 嚴禁憑想像寫出類似工具輸出的文字，也嚴禁在沒有取得來源的情況下宣稱「我擲了骰」或「抽籤結果是」。
- 第一次需要隨機時，用一行告知本局的隨機來源，例如「（本局隨機來源：C 玩家擲骰）」，之後不再重複，來源改變時才再說明。

## 三、roll.py 用法
```
python scripts/roll.py dice 2d6+1                    擲骰（NdM±K）
python scripts/roll.py check --dc 12 --mod 2         d20 判定：d20＋修正對照難度
python scripts/roll.py pick 甲 乙 丙 --count 2       從選項抽取，不重複
python scripts/roll.py alloc --items 項目1,項目2 --cap 略通 --min-low 3 --max-at-cap 1
                                                      在等第上限內隨機分配，可指定至少幾項為低等第、至多幾項達上限
```
- 預設輸出一行含工具名稱與時間的結果；加上 `--json` 輸出結構化結果。
- `check` 的分級：超過難度 5 以上＝大成功；達到難度＝成功；差 1 至 3＝勉強成功（成功但付出代價）；差 4 以上＝失敗。

## 四、通則
- 先宣告再取得結果：難度與可能後果在取得隨機結果之前決定。
- 結果不可更改：取得後不得重擲，不得因 PC 的期待而更動。規則明文允許的補救機制除外。
- 失敗也必須推進劇情。
- 機率只用來決定「世界如何回應」，嚴禁用來決定 PC 的選擇、想法或行動。
- 點數與修正值只在判定當下於後台使用，不寫入變數、進度總結或 NPC 資料；預設不向 PC 展示數字，以敘事白描呈現結果，PC 要求時再公開原始輸出。
